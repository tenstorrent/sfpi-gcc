sweep_native_gtle.c — native-compare lowering equivalence, GT and LE
float compare-against-+0.0 arms, exhaustive over 2^32 lane encodings each.

Semantics from the reference simulator:
  SFPSETCC  mod4 sign-clear, mod2 bits!=0, sequential AND under the
            running enable mask
  SFPCOMPC  fenced complement (stack top == entry enables)
  SFPGT     mod1==1 SET_CC arm
  SFPLE     mod1==1 SET_CC arm
  sign_mag32_total_order
ISA reference: tt-isa-documentation BlackholeA0 SFPGT.md / SFPLE.md
  (SignMagIsSmaller total order -NaN < -Inf < .. < -0 < +0 < .. < +NaN;
  SET_CC written under LaneEnabled, exactly like SETCC).

Build: cc -O2 -fopenmp sweep_native_gtle.c -o sweep_native_gtle
Run:   ./sweep_native_gtle

GT (x>0)   mismatches=0  web-stream=5779f68ae3934a24  native-stream=5779f68ae3934a24  EQUAL
LE (x<=0)  mismatches=0  web-stream=419f8f71c1934a24  native-stream=419f8f71c1934a24  EQUAL
RESULT: EQUAL over 2^32 x 2 directions

Stream commitments are position-salted FNV-1a 64 over (x, predicate)
pairs (per-chunk streams folded in fixed chunk order); equality per
direction plus mismatches=0 is the proof condition.

Covered classes: all normals, denormals, +-0 (web NE0 sees -0 =
0x80000000 as nonzero but the mod4 sign test already excludes it — the
total order agrees), +-Inf, +-NaN (the qNaN-admitting web shape is
REPRODUCED exactly by the total order against +0: +NaN > +0 holds in
both spellings).

SCOPE: the GT/LE float compare against +0.0 only, on the Blackhole
model only.  No lowering in this compiler emits the SFPGT/SFPLE SET_CC
form this proof covers (-mtt-tensix-optimize-native-compare is
accepted but has no effect).  The live compare lowering
(gimple-rvtt-pred.cc, expand_cmp_using_gtle) accepts arbitrary
operands, commutes LT/GE into GT/LE and covers SMAG and integer types;
this proof does not extend to it.
